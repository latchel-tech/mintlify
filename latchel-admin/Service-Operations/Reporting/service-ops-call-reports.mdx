<Accordion title="Description">
**1.** This Report queries the calls received in ZenDesk- Direction Inbound
- Status: Completed & Handled (cases where there is a hold time, duration, talk time)

**2.** Contain metrics related to each taken call- Duration (includes hold time, talk time, and wrap up) 
- Hold Time
- Talk Time
- Wrap up Time 
- Agent Name

**3.** This report helps us determine which Call Center won the call. - It joins the Twillio table to understand who won the call using the SID and the Phone Number.
This query uses our call_dueling table and filters out only those with status won (this filtering is done in the report, not in the query).  We’ll see a difference in this report versus the productivity call report because this is filtering out calls that are “abandoned throughout the path”.

**4.** This report uses the same tables as the one above (calls and call metrics), however, it has a filter to only include completed and inbound calls (excludes outbound calls).This is to understand all calls hitting ZenDesk.

**5.** This report is designed to track today's roll over data. It features a pie chart illustrating the proportion and number of calls completed by Latchel and each call center partner. Additionally, a graph is included to depict current call volume trends, with separate lines indicating the volume of calls handled by the Latchel call center versus calls that have rolled over to our partner call centers.

**6.** The table presents the distribution of incoming calls on an hourly and minute basis, along with the corresponding tally of distinct calls received during each hour. For instance: If the "Total Calls" value displays 10 in the row labelled 9 AM, this signifies that we received 10 unique calls spanning from 9:00 AM to 9:59 AM, encompassing the full hour of 9 AM.

**7.** This report is designed to track historical roll over data. It features a pie chart illustrating the proportion and number of calls completed by Latchel and call center partners. Additionally, a graph is included to depict current call volume trends, with separate lines indicating the volume of calls handled by the Latchel call center versus calls that have rolled over to our partner call centers.

**8.** The projected total cost for Latchel on call center invoices is estimated in this report. It's based on the duration of calls (in minutes), the cost per minute charged by call center partners, and the total number of calls managed by each partner call center.

**9.** This report contains the talk time, hold time, and wrap-up time per agent, as well as the total of these times for all team members handling calls.

**10.** This report displays the percentage of calls that are transferred to partner call centers during each day, broken down into hourly intervals (hourly roll over percentage).

**11.** This report displays the number of calls that are transferred to partner call centers during each day, broken down into hourly intervals (hourly roll over percentage).

**12.** 

**13.** This report displays monthly calls completed.

**14.** This report displays Latchel’s average handling time per month.
</Accordion>

<Accordion title="Query Used">
**1.**

```sql
SELECT c.phone_number, datetime(c.created_at,'America/Los_Angeles') as created_at, u.name,  c.duration, c.hold_time,  c.talk_time, c.wrap_up_time , c.completion_status,c.direction
FROM `data-analytics-warehouse.zendesk.call_metric` c
LEFT JOIN `data-analytics-warehouse.zendesk.user` u
 on c.agent_id=u.id 
 where u.name is not null
and direction='inbound' and completion_status='completed'
```

```sql
FROM `data-analytics-warehouse.zendesk.call_metric` c
LEFT JOIN `data-analytics-warehouse.zendesk.user` u
 on c.agent_id=u.id 
 where u.name is not null
and direction='inbound' and completion_status='completed'
```

**3.**

```sql
SELECT d.call_sid,
d.created_at, 
d.outbound_phone, 
d.status,
c.duration,
c.price ,
c.direction
FROM `data-analytics-warehouse.duelling_real_time_public.dueling_call_center_call` d
LEFT JOIN `data-analytics-warehouse.twilio.call` c
ON d.call_sid=c.id
WHERE DATETIME(cast(d.created_at as timestamp), 'America/Los_Angeles') BETWEEN  PARSE_DATE('%Y%m%d',@DS_START_DATE) AND  PARSE_DATE('%Y%m%d',@DS_END_DATE)
ORDER BY created_at DESC
```

## 🧠 What This Process Is Trying to Solve

<Note>
  We want to prevent confusion, inconsistency, and knowledge gaps across teams when creating new process documentation. The goal is to ensure every Latchel SOP is clear, self-explanatory, and follows a standardized format—so that anyone can independently learn, execute, or make decisions by following the instructions.
</Note>

## How to find the template

You can find the template when creating a new document by searching its name: "**SVC OPS SOP Template: \[Insert SOP Title Here\]**" in the side right panel.

## General guidelines

<Note>
  A Latchel SOP is a learning document that contains the content that you want to share with others. SOPs transfer **knowledge** and/or **skills** to the Latchel team at large scale. Topics can range from step-by-step guides, process guides, or situational-based guides. Typically each SOP is explaining a topic in details so the learner can execute actions or make decisions independently by following the SOP instructions. Therefore, the SOP should be a self-explanatory document that should stand on its own.

  This is a guide to help you to create high quality SOPs that meet the standard set forth by Latchel. The objective is that all Latchel learning documents created from across teams are consistent in notation, organization, and overall quality.
</Note>

- Refer to this document **to know and use the existing official Latchel terminology** [Latchel's Terms and Definitions](https://latchel.atlassian.net/wiki/spaces/LTG/pages/2545811472/Latchel+s+Terms+and+Definitions).
  - If needed, you can use "Find and Replace" mode by clicking "ctrl\+F" to update any outdated terms in your document.
- Use a **numbered list** to describe **steps** that need to be taken in **a certain sequence.**
- Use a **bullet list** to show **a list of items** that do not need to be described in an specific order.
- **Don't combine multiple steps into a single bullet**, each bullet needs to be a single step.
  - Use indentation ("Tab" key) to list steps that fall within another process.
- Use **quotation marks to explicitly mention** options within the application (e.g. Click the "Take Action" button).
- **Bold, italics, underline, text colors:** are helpful when you want **to draw the attention** of the reader to an important point within regular text.
- Refer to the following link for information on how to use the confluence editor toolbar: [https://confluence.atlassian.com/doc/the-editor-251006017.html](https://confluence.atlassian.com/doc/the-editor-251006017.html)

<Danger>
  Do NOT use emojis in the title.
</Danger>

## Keep it digestible and maintainable

- **Try to maintain the text in the SOP to a minimum** so that the SOP is easy to consume. Long SOPs are difficult to digest and quickly forgotten.
- Images are also a good resource to explain clearly with minimum text.
  - When using images, use a software tool that allows you to markup screenshots/images to focus the attention of the reader to the relevant part of the image.
    - Some software tools are: "Paint" (included with Windows), "Google Slides", "Lightshot" (Google chrome extension), etc.
- **Refrain from explaining guided workflows of the platform**, unless the workflow can lead the agent to an incorrect action, explaining each step adds complexity to the SOP and makes SOP maintenance harder.
  - Having to explain a guided workflow is an indication that the workflow itself is not intuitive and this needs to be fixed with product updates.
- **Always refer to existing SOPs** **when an action** needs to be performed that **is already documented** somewhere else. **Do not duplicate information**, this is important so that we have **one single source of truth.**
  - For example, see the following text extract and notice how it refers back to an existing document:
    - "The following documents will explain how to assess an emergency situation and determine if emergency dispatch is required or if the emergency can be de-escalated. It is also important to check for any potential duplicates to avoid double dispatch of vendors and determine if there's potential for property damage.
      - To determine if there's potential for property damage refer to: [↔ Job Aid: Defining Property Damage](https://latchel.atlassian.net/wiki/spaces/OPS/pages/745504771/How+to+Identify+Property+Damage+and+Extreme+Habitability+Situations)"
    - Linking to other Published SOPs can be easily done when you copy the URL of the Published SOP and paste into the document, it automatically becomes its own link.
    - This can also be done by linking to existing page by clicking "ctrl\+k".

## Panels

<Tip>
  Use this type of panels for **tips** (For example: Blurbs)
</Tip>

<Warning>
  Use this type of panel **to caution** about doing something **or** for **important reminders** through out the process.
</Warning>

<Danger>
  Use this type of panel for **critical actions or behaviors that need to be avoided** (e.g. "Never provide a Property Manager's private contact information to the resident")
</Danger>

## Reviewing the draft

1. **After creating a new page, it is automatically a "Draft"** until you hit the "Publish" button on the upper right.
   <Frame>
     ![](/images/SVC-9.png)
   </Frame>
2. If you need to **save the changes without publishing, just click "Close"**
3. It's best to **review documents inside of confluence** because that will allow you to see the final format.
   1. Share the draft with any stakeholders for review by copying the URL of the draft.
   2. Reviewers can add comments to the draft by highlighting the related text and clicking "comment"

## Labels

- We will use labels to manage content, make for search-ability within the Latchel Library, and to auto populate new content (of the same theme) using the "content-by-label" feature.
  - Learn more about Labels here: [https://confluence.atlassian.com/confcloud/use-labels-to-organize-your-content-724764874.html](https://confluence.atlassian.com/confcloud/use-labels-to-organize-your-content-724764874.html)
  - Use the following guidelines to use labels:
    - By Roles:
      - Troubleshooter, Ops Associate, Operations Support Specialists, Trainers, Quality Associate, S&R
    - By Subscription types
      - Premium, Autopilot, 24/7
    - By agent workflow:
      - Tasks, call center, emails, SMS/webchat.
    - By Work Order workflow
      - Scheduling, Finding Service Provider, Scheduling with Service Provider, Scheduling with Resident, Awaiting Work Date, Confirming Completion, Awaiting Invoice Receipt, Completed, Pending.

## 🎯 When to Break This SOP

**Do not break or deviate from this SOP on your own authority.** Always escalate to an Ops Support specialist or follow explicit instructions if you believe an exception is necessary.

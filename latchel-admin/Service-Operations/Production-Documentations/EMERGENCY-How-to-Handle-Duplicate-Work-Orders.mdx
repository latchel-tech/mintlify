<Note>
  We want to prevent double-dispatching, confusion, and missed emergencies caused by duplicate work orders for the same issue. The goal is to help troubleshooters quickly identify and handle potential duplicates during emergencies—so we avoid wasted resources, ensure every urgent request is addressed promptly, and deliver a seamless experience for both customers and Latchel.
</Note>

## 📋 Step-by-Step Process

When a single unit experiences the same issue, creating multiple work orders can lead to confusion and potential duplicate dispatches. To avoid this, it is important to review and verify any existing work orders for the same issue within that unit. The following process should be followed when managing duplicate work orders for the same unit.

For widespread utility outages, refer to: [(Emergency) How to: Handle a Utility Issue](https://help.latchel.com/\(Emergency\)-How-to-Handle-a-Utility-Issue)

For duplicate issues affecting building-wide incidents, refer to: [SOP: Building-Wide Emergency Work Orders](https://help.latchel.com/SOP-Building-Wide-Emergency-Work-Orders)

### Emergency Troubleshooting Tasks

Emergency Work Orders (WOs) will sometimes populate with a message under the property section, indicating to the user that there are other active jobs for the given property address.

Additionally, you can identify if there is an active work order related to the current one by checking for a project listed just below the work order number. If the project title is "Additional Issues Detected," this indicates that Harmonia has generated a secondary work order related to the main issue. In such cases, you will need to review the work order to confirm that it is not a duplicate and that it represents a valid secondary issue. Please follow the guidelines outlined here: [Service Ops: Handling Multiple Work Orders Generated by Harmonia Intake](https://help.latchel.com/Service-Ops-Handling-Multiple-Work-Orders-Generated-by-Harmonia-Intake).

Go to the property section and you will see this message. You should be careful to verify that the new job is not a duplicate.:

<Frame>
  ![Message indicating other active jobs for the property](/images/SVC-244.png)
</Frame>

- Click the link to the other Work Orders to review each one and understand if they may be a duplicate or not.

<Warning>
  Prevent DOUBLE escalation to property managers and DOUBLE dispatch to Service Providers!
</Warning>

- Compare previous work orders from the same property and confirm that the issue description is similar. Usually, the skills can differ according to how the resident submitted the Work Order in their portal. Sometimes, a different resident living in the same household can create a new work order. Matching descriptions of the issue will confirm that the most recent work orders are a duplicate.

<Note>
  📝 NOTE: There are also cases when there are duplicate Work Orders that have already been archived. We may not be able to see this right away through the Property Maintenance tab but here is one way you can check for it. Refer to the guide on [How to Search for Archived Work Orders](https://help.latchel.com/Job-Aid-Finding-an-Existing-Work-Order-vs.-When-to-Create-a-new-Work-Order#how-to-search-for-archived-work-orders).
</Note>

- Check the status of the previous work orders. After the description, the status of the work orders is crucial to identify if we have a duplicate. Statuses such as Pending, Waiting for Owner's Approval, Scheduling with the Service Provider, Confirming Completion, Waiting for PM, and Forwarded to PM reflect a pause in the Work Order. As a result, residents may not have received updates recently, leading them to create a new submission.

When handling a duplicate Work Order that is archived, follow these steps:

- If the archived work order is in an open states (Pending, Scheduling, etc), follow Step 3 of (⛑EMERGENCY) How to: Handle Duplicate Work Orders
- If the archived work order was previously marked as Completed or Awaiting Invoice status, follow the recall process; [How to: Identify and Handle a Recall WO](https://help.latchel.com/How-to-Identify-and-Handle-a-Recall-WO)

<Note>
  📝 NOTE: Ops should create a task (on the archived WO) to notify the PM that the Work Order has been found to be archived. In the task, clearly explain why the WO needs to be reopened or why further work is required. This clarification will help the PM understand the necessity for additional action. Due to the archived status, the Work Order may not appear in the PM's view. The PM may choose to either reopen the WO for further work or leave it archived for their own visibility and tracking.

  Please ensure this explanation is clear and detailed to avoid any confusion regarding the status and the next steps needed for the WO. Please see the sample below:
</Note>

<Frame>
  ![Sample task notifying the PM about an archived work order](/images/SVC-245.png)
</Frame>

- Keep dates in mind. Besides the description of the issue and the status of the work order, timing is one of the most important signals of a duplicate.

A work order submitted within hours or days of a previous submission with a matching description and status is considered a duplicate if:

- The original WO was unresolved or unattended.
  - The duplicate occurs when the initial work order has not been updated or addressed.
  - (Resident reported that the issue was unaddressed, and no technician visited to assess the problem.)
  - An open work order will remain the primary reference for 180 days. Any subsequent submission received within this 180-day timeframe will be treated as a duplicate and associated with the original work order. Submissions received after 180 days may be acknowledged and handled independently.
  - If a work order is submitted after days, weeks, or a longer period, it may be classified as a recall, provided it meets the recall criteria. Refer to [How to: Identify and Handle a Recall WO](https://help.latchel.com/How-to-Identify-and-Handle-a-Recall-WO)
- The original work order was completed/fixed.
  - The same Service Provider may return to address the issue.
  - The work order recurs within 180 days of the original closure.

If the duplicate was created because the resident did not receive an answer in a timely manner, follow these tips to improve your communication at the moment of calling: Be prepared and become familiar with the work orders. This will allow you to answer questions in general and explain to the resident what is going on with their original request. Verify if the new WO is an update related to the severity. In case the issue has worsened, use the [Job Aid: Troubleshooter Question Bank](https://help.latchel.com/Job-Aid-Troubleshooter-Question-Bank) to troubleshoot, requesting new photos/videos. If helpful, you can offer video troubleshooting. Update the original WO and cancel the duplicate.

- If the other job is a Work Order regarding the same maintenance request for the same property, then this is a Duplicate Work Order and one of the Work Orders needs to be canceled.

<Note>
  📝 NOTE: if the previous Work Order was canceled, do NOT cancel the new one and work on it as a standard WO.
</Note>

- Read the suspected Work Orders to understand their history.
- Contact the resident to verify that the Work Order is a duplicate.
  - Refer to [(TECH 101) How to: Make Outbound Calls Within the Latchel Console](https://help.latchel.com/\(TECH-101\)-How-to-Make-Outbound-Calls-Within-the-Latchel-Console) to make the outbound call.
  - Refer to [Job Aid: How to Properly Diagnose Emergency Situations](https://help.latchel.com/Job-Aid-How-to-Properly-Diagnose-Emergency-Situations) for guidance on how to evaluate the situation.
- Explain the status of the original Work Order and inform that the duplicate(s) will be canceled.
- Add the term "Duplicate" at the beginning of the work order title

<Frame>
  ![Adding the term Duplicate to the work order title](/images/SVC-246.png)
</Frame>

- Cancel the duplicate Work Order via the take action button.
  - In most cases, the most recent Work Order is the one that needs to be cancelled, but if you're unsure escalate to the the Operations Support Specialist team via the #ops\_assistance\_hub for assistance.
- Place a note indicating that the work order has been cancelled due to being a duplicate. Be sure to include the work order number and a link for easy access.

<Frame>
  ![Note indicating the work order was cancelled due to being a duplicate](/images/SVC-247.png)
</Frame>

- If the resident was unresponsive to our contact attempt to verify if the WO is a duplicate of another request: a. Proceed with selecting the option "Can't Reach Resident", refer to How to: Handle Emergency Work Orders i. This should include all work orders that seem like duplicates, especially those with similar or identical summaries. ii. Make sure to mention in your guided workflow notes that this might be a duplicate of another work order. Additionally, describe the status or what's required for the other request.
- If the other job is a Work Order that is regarding a different maintenance request for the same property, then this will be worked as a New Work Order. There is no duplicate Work Order to handle.
  - Continue as normal.
  - (⛑OVERVIEW) How to: Handle Emergency Work Orders

Escalate to the support team via the #ops\_assistance\_hub channel if you require assistance.

### Frequently Asked Questions

**How do we handle duplicate work orders created by PMs?**

Today, PMs create duplicate Work Orders (WO) intentionally for the purpose of getting additional estimates from preferred vendors. While these WOs were created intentionally, our team occasionally cancels these WOs, resulting in delays and additional work for the PM. In order to solve this issue, we've rolled out a feature on the PM side where we ask them to confirm that they're creating the duplicate WO intentionally (see screenshot below). As a result, we now can assume all duplicates created by PMs do not have to be deleted. The purpose of this SOP is to inform Latchel Operators how to check for PM duplicate WOs.

<Frame>
  ![PM confirmation screen for intentional duplicate work order](/images/SVC-248.png)
</Frame>

When following the SOP for checking for duplicate WOs, first check to see who created the WO.

<Frame>
  ![Checking who created the work order](/images/SVC-249.png)
</Frame>

If the person who created the WO is a PM, DO NOT delete the WO if it's a duplicate. The PM has confirmed through the new feature that they have created this duplicate WO on purpose. If it's created by a tenant or internally through Latchel, then please follow the Duplicate WO SOP today.

## 🎯 When to Break This SOP

Do not break or deviate from this SOP on your own authority. Always escalate to an Ops Support specialist or follow explicit instructions if you believe an exception is necessary.

If you believe, it is not a duplicate but a recall, follow the process for recall work orders. Refer to [How to: Identify and Handle a Recall WO](https://help.latchel.com/How-to-Identify-and-Handle-a-Recall-WO).

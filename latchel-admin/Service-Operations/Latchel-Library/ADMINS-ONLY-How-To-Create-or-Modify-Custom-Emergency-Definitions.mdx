## Objective

<Info>
  This page is to show how to create or modify custom emergency definitions for (on behalf of) Property Managers.
</Info>

<Info>
  This SOP is only for Admins on the Latchel team. Problem Solvers, Customer Success, and other Latchel Management should review this SOP.
</Info>

<Info>
  - While being Onboarded into Latchel, the customer fills out a Google Form (located here: [https://docs.google.com/forms/d/1mkY5aIGrf1WPb9pPdAW2-iP-ytau4nhdudiGVs549zQ/edit#responses](https://docs.google.com/forms/d/1mkY5aIGrf1WPb9pPdAW2-iP-ytau4nhdudiGVs549zQ/edit#responses)). These responses are saved to the Customer Success Shared Drive (located here: [https://drive.google.com/drive/folders/0AFgDMfQ0JDDiUk9PVA](https://drive.google.com/drive/folders/0AFgDMfQ0JDDiUk9PVA)).
  - These responses are used to complete and fill-out the Property Manager customer's unique Emergency Definitions.
  - Additionally, a Property Manager may request changes to their custom Emergency Definitions at any time; these modifications may apply for the Company overall or on the Portfolio level.
</Info>

### Step-by-Step Guide

#### **Step 1 - Navigate to the Admin Menu from the Latchel Console.**

  ![Image](/images/LL-87.png)

<Note>

#### **Step 2 - Select "Troubleshooting Flows"**

<Frame>
  ![Image](/images/LL-88.png)
</Frame>

<Warning>
  The "DEFAULT" work flows should never be edited. These workflows are used by the majority of the systems.
</Warning>

#### **Step 3 - Select the workflow you wish to edit OR Create a new Workflow**

1. **I want to edit anexistingWorkflow.**
   1. **Select the existing workflow you wish to edit**

<Frame>
  ![Image](/images/LL-89.png)
</Frame>

2. **I want to create a new Workflow.**
   1. **Option 1: Copy an existing workflow and build a new one based on the workflow you copied (or "Cloned").**
      1. **_Why copy an existing Workflow?_**  Templates save time! Cloning an existing Workflow can be useful as a jumping point to create a New Workflow if the workflows should be fairly similar. It becomes a matter of customizing the Workflow through edits instead of building from scratch.
      2. From the far right side of the existing Workflow title, navigate to the three dots.
         1. Click on the three dots to reveal the option to "Clone" the existing Workflow title.
            <Frame>
              ![Image](/images/LL-90.png)
            </Frame>
3. **Option 2: Create a new workflow from scratch.**
   1. Navigate to the top of the "Troubleshooting Flows" Menu.
      1. Click "\+ New Flow to begin a new workflow from zero.
         <Frame>
           ![Image](/images/LL-91.png)
         </Frame>

#### **Step 4 - Add new questions to prompt the interaction between the agent and the Resident.**

<Note>
  Each subsequent question is nestled within its previous question, somewhat like the layers of a nesting doll. _Image: Matryoshka Nesting dolls_.

  <Frame>
    ![Image](/images/LL-92.jpeg)

</Note>

- The initial question should**always** be: **"What issues are you experiencing?"**
  - This prompts the conversation between the agent/system and the resident.
- From there, you can begin adding answers.

<Frame>
  ![Image](/images/LL-93.png)

- Each answer will appear on its "Parent Question"

<Frame>
  ![Image](/images/LL-94.png)

#### **Step 5 - Choose the Next Step**

Once the "Answer Text" to the "Parent Question" has been filled-out, the user must choose the next logical step for this answer.

1. Choose "Create Work Order" to fillout the criteria for setting the auto-creation of a new Work Order, or,
   1. [Review Step 5.1 for the subsequent path possibilities for "Create Work Order"](#id-\(ADMINSONLY🏡\)HowTo:CreateorModifyCustomEmergencyDefinitions-step5.1)
2. Choose "Prompt Resident" with another question.
   1. [Review Step 5.2 for the subsequent path possibilityes for "Prompt Resident"](#id-\(ADMINSONLY🏡\)HowTo:CreateorModifyCustomEmergencyDefinitions-step5.2)

<Frame>
  ![Image](/images/LL-95.png)
</Frame>

##### **Sub-Step 5.1 - When the Next Step is to "Create Work Order"**

1. "Create Work Order" is the logical end of each path of possibilities.
2. This is where Latchel determines that an action should be taken. 

With "Create Work Order", the user must set the following (3) criteria:

1. **"Job Severity**"
   1. **"Job Severity**" -This is the priority of work order that is to be created. (Emergency, Urgent, or Normal)

<Frame>
  ![Image](/images/LL-96.png)
</Frame>

2. **"Job Category"**
   1. **"Job Category"** This is the skill category that will be required to service this issue.
      1. Use the "Service Provider Skills and Definitions" SOP resource to determine the Job Category as this Work Order is being Created. [↔ Job Aid: Service Provider Skills and Definitions](https://latchel.atlassian.net/wiki/spaces/OPS/pages/791119550/Admins+Only+Job+Aid+Service+Provider+Skills+and+Definitions)

<Frame>
  ![Image](/images/LL-97.png)
</Frame>

3. **"End Message"**
   1. **"End Message"** This is the final message that will be presented to the customer during work order creation.

<Frame>
  ![Image](/images/LL-98.png)
</Frame>

##### **Sub-Step 5.2 -When the Next Step is to"Prompt Resident"**

1. "Prompt Resident" leads to another question, which will then have its own set of answers.
2. The user must provide the questions, and add each possible answer following it.
   1. The user must then select a resolution for each of those answers.
3. This option could result in:
   1. A new Question Set,
   2. A Work Order to be created, or,
   3. A Prompt for the Resident to contact someone else.

<Frame>
  ![Image](/images/LL-99.png)
</Frame>

#### **Step 6 - Name the Workflow and "Save Flow"**

1. If this is a new Custom Emergency Definitions Workflow, you must give a name to the workflow at this time.
   1. If this Workflow is exclusive to a Property Manager, name it after that Property Manager group (e.g. "Jimmy John's Property Management").
   2. If it is a generic Workflow, name it after its defining features (e.g. "HVAC Excluded from Emergency").
      1. **Note:** Make sure that the chosen name is detailed and understandable.
2. All Custom Emergency Definitions Workflows **must be 💾"Saved"** after the last change has been made to the workflow.
   1. Progress will not be stored if the user odes not click **"Save Flow"** after completing work..
   2. **🔥Hot Tip**. Save the workflow as you build each step to mitigate the risk of losing the work you have done
3. To Save the workflow, type the name, enter a Description (giving more contextual information regarding that Workflow) and click on **"Save Flow".**

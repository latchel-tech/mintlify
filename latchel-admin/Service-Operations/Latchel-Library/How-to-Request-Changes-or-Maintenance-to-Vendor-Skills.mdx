## Objective

<Info>
  The purpose of this document is provide guidance on how to request maintenance or changes to vendor skills using the Workflow in Slack channel #skills-and-troubleshooting.
</Info>

<Info>
  An agent has identified an error or oversight in the vendor skills lists.

  - This could be from a skill that is missing (Section 1 - New Skill Request), a skill that was described incorrectly (Section 2 - Change Skill Description), a skill that is in the wrong category (Section 3 - Change Skill Category).
  - An agent can also report when a Property Manager or Service Provider states that the wrong provider or skill was assigned (Sections 4 and 5).
</Info>

### Step-by-Step Guide

**Overview of Slack channel #skills-and-workflow-issues Workflow options**

</Info>

#### **Section 1 - New Skill Request**

<Info>
  A new skill request is required whenever an user has identified that there is a gap in the offerings of available skills.
</Info>

<Frame>
  ![Image](/images/LL-128.png)
</Frame>

<Note>
  If a skill is missing and you require the skill to continue dispatching an Emergency Priority Status Work Order, please **dispatch under the "General" category most relevant to that skill.** Then Proceed to notify and request the change via Slack at #skills-and-workflow-issues channel.
</Note>

<Frame>
  ![Image](/images/LL-129.png)
</Frame>

<Frame>
  ![Image](/images/LL-130.png)
</Frame>

1. **Request name (short description of your request)** Enter a short name to identify your request
2. **What type of request is this?** Here you will select either "Skill change request" or "Skill add request"
3. **What is the requested change from the current set up?** Here you will describe how adding or changing the skill will change the current process.
4. **What is the reason for this change?** Here you will describe why you think this change should take place
5. **How does this impact or improve the user/customer experience? Work backwards from the customer!**
6. **What is the severity of this request?** Here you will select if the request is low - Individual productivity is impacted, medium - Group productivity is impacted, or high - Business critical function is impacted.
7. **Please define why you've chosen the severity above (i.e. how often is this an issue? can you quantify the impact?)**
8. **Any additional details (optional)**

#### **Section 2 - Change Skill Description [FBL-44](https://latchel.atlassian.net/browse/FBL-44)**

<Info>
  Change Skill Description is to be used whenever a skills given description does not match common uses, or there is a mistake in the way it is written.If you would like a description modifier to this skill (IE "We use this skill when the resident states XXXX problem.) you may also request using this option.
</Info>

<Frame>
  ![Image](/images/LL-131.png)
</Frame>

1. **What is the name of this skill?** Provide the name of the skill in question.
2. **What is the current description?** Copy the current description into this section.
3. **What is the proposed change?** State where the mistake is and what it should be changed to.

#### **Section 3 - Change Skill Category**

<Info>
  Change Skill Category is to be used whenever a skill is believed to be in the incorrect skill category. (e.g. Replacing a light fixture is listed under the Plumbing Category.)
</Info>

<Frame>
  ![Image](/images/LL-132.png)
</Frame>

1. **What is the skill?** Provide the name of the skill.
2. **What is its current category?** Provide the current category the skill is in.
3. **What is the recommended category?** Input the name of the recommended category.
4. **Any additional information?** Add any additional information that is needed to make a determination.

#### **Section 4 - Provider States-Wrong Skill**

<Info>
  Provider States Wrong Skill has been used. This is whenever a provider has been assigned a job,

  [FBL-45](https://latchel.atlassian.net/browse/FBL-45) but later informs Latchel that they do not have the skill to complete this job. Customer Service is still to be the priority, and the job should be reassigned accordingly, but this action should be completed to trigger a deep dive to correct the issue.
</Info>

<Frame>
  ![Image](/images/LL-133.png)
</Frame>

1. **Link to provider profile:** Provide the link to the providers profile in the Latchel Console.
2. **Link to Job:** Provide a link to the job that is being referenced.
3. **Skill Trade/Name:** Provide the name of the skill that needs to be addressed.
4. **Additional Information:** Provide any relevant information that may be needed to make a determination for action.

#### **Section 5 - PM States Wrong Provider**

<Info>
  PM States Wrong Provider is to be used

  [FBL-46](https://latchel.atlassian.net/browse/FBL-46) whenever a Property Manager calls to inform Latchel that a dispatched Service Provider should not have been sent to the job. This will trigger a deep dive to find the breakdown if there was one.
</Info>

<Frame>
  ![Image](/images/LL-134.png)
</Frame>

1. **Which PM is making the claim?** Provide a link to the Property Manager's profile.
2. **What Service provider is being referenced?** Provide a link to the profile of the service provider being referenced.
3. **What work order is being referenced?** Provide a link to the relevant work order.
4. **What is the complaint and suggested resource?** Provide detailed information for why the Property Manager is unhappy and what is recommended to correct the issue from happening again.

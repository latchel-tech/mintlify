## Major Updates

[How to: Handle Emergency Work Orders](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-Emergency-Work-Orders)

**Why it matters:**

- Associates needed clearer guidance on common area emergencies, access/lockout scenarios, and a recurring edge case where the wrong person answers the outbound call.

**What changed;**

- **[Major]** Common area emergency handling — previously routed to the **Cannot Reach Resident** path → now has a dedicated flow (**Step 1.2.c** ) with specific steps and [escalation paths for common area emergenci](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-Emergency-Work-Orders)[es](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-Emergency-Work-Orders), lockout, and access-related scenarios. ()
- **[Minor]** Resident has no availability / no entry permission — previously had two conflicting instructions (one sending associates to live escalation, another to create a manual PM task) → now consolidated into a single upstream trigger pointing to **"PM Input needed before dispatch"**; non-PD/EH outcome is now also documented inside that section. (**Option 2 1.d.ii.4**)(**Option 2 1.d.iv.1.c/e ****)(Option 2 1.d.iv.2.c ****)**
- **[New]** FAQ added — [*Wrong Person Answered the Phone (Suspected Incorrect Number on File*](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-Emergency-Work-Orders)*)* — previously no documented guidance → associates now have a defined path for this scenario

**What you need to do:**

- Review the updated SOP, specifically the common area and lockout/access sections
- When a resident has no availability and entry permission was not granted, go directly to **"PM Input needed before dispatch"** — no manual PM task needed
- Familiarize yourself with the new FAQ for incorrect number scenarios

**When it takes effect:**

- *Monday, *

## 🧠 What This Process Is Trying to Solve

<Note>
  We want to prevent delays, duplicate outreach, and miscommunication when scheduling appointments with service providers. The goal is to ensure every work order in "Scheduling With Service Provider" status is handled efficiently and consistently—so appointments are confirmed quickly, all parties are kept informed, and customers experience smooth, frustration-free service from Latchel.
</Note>

<Note>
  **What are Work Orders with "Scheduling Service Provider Status"**

  Those are work orders that are waiting on a vendor to schedule the maintenance appointment after they were assigned to the Work Order by the Property Manager or Latchel. The purpose of this SOP is to guide Latchel Operators around when and how to handle Work Orders in the "Scheduling with Service Provider" status.
</Note>

<Warning>
  If you encounter one of the following scenarios, please leave a note on this page and transfer the work order _to the Property Manager_. [(Operations) How to: Escalate Between Teams](/latchel-admin/Service-Operations/Production-Documentation/How-to-Escalate-Between-Teams).

  This may include:

  - If a property has permission to access but no access instructions or is vacant.
  - If the Service Provider says that they'll contact the resident directly and refuses to update Latchel.
</Warning>

<Warning>
  Attention: For agents handling tasks for both emergencies and non-emergencies.

  Before you begin working on any task, ensure you view all open tasks for the customer you are following up on (resident, service provider, owner). This step is crucial to avoid duplicating efforts and customers complaints, and to ensure we always get it right the first time.

  For detailed instructions on how to handle the tasks queue and view all open tasks, please refer to the following link: [How to: Work the Tasks Queue](/latchel-admin/Service-Operations/Production-Documentation/How-to-Work-the-Tasks-Queue).

  For information on the frequency and number of times you should contact customers, please refer to [Informational: Basic Service Ops Guidelines and Rules](/latchel-admin/Service-Operations/Production-Documentation/Informational-Basic-Service-Ops-Guidelines-and-Rules).
</Warning>

<Warning>
  **LVN Service Provider**

  For guidance on managing unresponsive LVN service providers or on acceptable scenarios for reassigning an LVN service provider (such as PM requests or missed appointments), refer to [Handling Work Orders Assigned to LVN Service Providers](/latchel-admin/Service-Operations/Production-Documentation/Handling-Work-Orders-Assigned-to-LVN-Service-Providers).
</Warning>

<Warning>
  For LCN service providers exhibiting observable behaviors—such as missed appointments or unreasonable excuses—that result in scheduling delays, ensure to update their critical note to reflect the missed appointment or scenario encountered. Follow the format below, as it will be used in the future to determine whether we can continue offering jobs to the service provider.

  **Critical Note Format:**

  📌 _Date | WO# | Missed Appointment/Unreasonable Behavior_

  If they miss **three consecutive WO appointments or unacceptable behaviors**, their profile can be disabled. Associates are expected to check recent work orders to identify any recently completed WOs, which may indicate a successful appointment. Refer to the 3rd step in [How to: Navigate Service Provider Profiles](/latchel-admin/Service-Operations/Production-Documentation/How-to-Navigate-Service-Provider-Profiles) to disable a service provider’s account. Ensure to leave notes as well why they were disabled.
</Warning>

## 📋 Step-by-Step Process

### **Step 1: About the "Scheduling Service Provider" status**

<Note>
  **⚠️ Confirm the Correct Work Order Before Scheduling**

  Before reaching out to the resident/service provider to schedule, verify that the task is linked to the correct Work Order. Scheduling against the wrong WO can lead to a service provider being dispatched to the wrong property or for the wrong issue.
</Note>

1. The Service Provider Work Queue populates with a Work Order whose status is: "Scheduling Service Provider"
   1. **_What does it mean?_** Prior to this stage of the Work Order, the resident has given their time availability and the job has been assigned to a service provider.
      1. The Latchel Console system automatically moves the work order into "Scheduling Service Provider".
   2. When a Work Order is in this status, Operations Associates have the following responsibilities:
      1. Checking the progress with contacting the Service Provider by reading notes on the Work Order.
      2. Making a phone call to the Service Provider via our Latchel Console.
         1. Keep in mind that some service providers may have critical notes with special instructions outlining how they prefer to interact with Latchel.
      3. Depending on the scenario, executing one of the following:
         1. Escalating the Work Order to Leadership or the Property Manager
         2. Deferring the task
         3. Transferring the Work Order to Operations Support Specialists or sourcing
         4. Moving the Work Order status forward by scheduling an appointment.
2. Open the Work Order
   1. Proceed to Step 2 below

### **Step 2: Read the Work Order**

1. Read the Work Order and check to see if there is availability from the resident. You can see this by clicking on the residents' profile and selecting the "Schedule" tab.
   1. If there is no additional Resident availability, return the work order to "Rescheduling with Resident" status. You can do this through the following steps:
      1. From the Action button, select "Reschedule This Job".
      2. The system will then ask the resident to update their availability.
   2. If there is more Resident availability, proceed to check the notes of the Work Order to see how many attempts have already been made to contact the assigned Service Provider.
      1. **📝 NOTE:** Operations Associates will only attempt to contact the Service Providers **<u>2 separate times</u>**.
2. Review the Work Order notes to see if another Latchel Associate has already tried to contact this Service Provider to schedule the appointment.
   1. If Latchel has contacted this Service Provider 0x or 1x before, please proceed to [Step 3](#).
      1. ⚠️ **Before removing the SP from the job, first confirm whether the SP is locked in or has already visited the property.** If either is true, **do not remove** — proceed to Step 4, section 2.a (escalate to PM). If neither is true, proceed to Step 4, section 2.b (reassign).
   2. If Latchel has contacted this Service Provider 2x before, please proceed to [Step 4](#).
      1. If we've already called the Service Provider 2x, we will be removing this Service Provider from the job and allow auto-assign to continue to offer it to the remaining preferred Service Providers.
      2. **📝 NOTE** Please don’t send any other follow-up or message to the vendor that is being removed from the job or to the new vendor.

### **Step 3: Calling the Service Provider and Resident**

Call the Service Provider one time (1x) a day using the Latchel Console ( [↔ How to: Make Outbound Calls Within the Latchel Console](/latchel-admin/Service-Operations/Production-Documentation/How-to-Make-Outbound-Calls-Within-the-Latchel-Console)) and follow the script below (replacing the fields in purple with specific information).

- **📝 NOTE** Always attempt to contact the service provider first via phone call. SMS and email should only be used if we are unable to reach them by phone. Exceptions include cases where they don't have a valid phone number, it's outside of 9:00 am-5:00 pm, or if there are special communication instructions in the critical notes.

<Tip>
  **Service Provider Call Script**

  **Preferred**

  _Hello! This is **(insert Associate Name)**, I'm calling from Latchel on behalf of **(insert PM Company Name)**. I am reaching out to you today because I see that we have a job assigned to you, but we still need to confirm an appointment with you. The resident has availability at (Date and Time from Resident availability list) Do any of those times work for you?_

  **LCN/LVN**

  _Hello! This is (**insert Associate Name**), a Maintenance Coordinator calling on behalf of **(insert PM Company Name)**. I am reaching out to you today because I see that we have a job assigned to you, but we still need to confirm an appointment with you. The resident has availability at (Date and Time from Resident availability list) Do any of those times work for you?_
</Tip>

From the call, you will encounter 1 of the 6 outcomes below.

#### **<u>OUTCOME 1</u>**: If the Service Provider answers the phone call and he/she agrees to set an appointment in the windows of availability, then:

1. Select "Action, and Select from Resident Availability". Then say:

<Tip>
  **Service Provider Confirmed Schedule Script**

  I have assigned the work order to you. In the event the scheduled appointment is missed, we will only attempt to contact you <u>twice</u> before reassigning.
</Tip>

2. Select the agreed upon window and then select continue
3. In the notes section, explain why you took this action, i.e. "per phone call with vendor confirmed scheduled appointment"
   1. **_Why?_** This removes this Work Order from the queue and moves it into the " Awaiting for Work Date" status. Please note that when this process happens, this will cancel out the deferred task and the task will not return to the "Scheduling" task queue.
4. Proceed to writing an Effective Note in [Step 5](#).

#### <u>OUTCOME 2:</u> If the Service Provider answers the phone call and he/she cannot schedule within the resident's availability, then:

1. Follow the script below:

<Tip>
  **Service Provider Additional Openings Script**

  Ok, I understand, may I get your openings for the next couple of days to pass along to the resident? We can't guarantee that they will accept it, but I can try. Please note that if the resident cannot adjust their availability, then the job will be reassigned to another provider without notice. Thank you!
</Tip>

2. Collect the Service Provider's availability.
3. Then contact the resident and ask for further availability.
   1. If the Resident is **<u>available</u>** for the newly updated Service Provider's availability, then schedule the appointment with the Resident. You can do this from the Work Order interface by:
      1. Clicking the secondary action button.
      2. Choose "Set a New Confirmed Work Date".
      3. Follow system prompts until you successfully schedule the new Work Date and Time Window.
   2. If the Resident is **<u>not available</u>** during the newly updated Service Provider's availability, then:
      1. Reassign to another Service Provider (proceed to [Step 4](#))
      2. Ask the Resident, if they have any new available time slots. Update this new time slot information in the Latchel Console.
   3. Proceed to writing an Effective Note in [Step 5](#).

#### **<u>OUTCOME 3:</u>** If the Service Provider answers, but says they cannot talk now and will call back.

1. Send an SMS with the template below. If the Service Provider does not have a textable number, then send an email with the template below.

<Tip>
  **Service Provider Scheduling Reminder SMS Template**

  This is a reminder from Latchel to schedule the job at (insert Property Address) within the next 24 hours. This can be done via our online portal or by calling (_please refer to [Informational: Latchel Communication (Phone Numbers)](/latchel-admin/Service-Operations/Production-Documentation/Informational-Latchel-Communication-Phone-Numbers) for the appropriate phone number_). Otherwise, the job will be reassigned without notice. Thank you!
</Tip>

2. Defer the task for the next business day at 9:00 AM local time for the contact. Business day is defined as weekdays and does not include holidays. For example, if it's Friday, please defer the task for Monday.

#### **<u>OUTCOME 4</u>**<u>:</u> If the Service Provider does not answer the phone call, then:

1. Leave a voicemail using the template below (replacing the 4 fields in pink with specific information) and also send an SMS. If the Service Provider does not have a textable number then send him/her an email instead.
   1. **Preferred**:  _Hello! This is **(insert Associate Name)**, I'm calling on behalf of **(insert PM Company Name)**. We have a job assigned to you at (insert Property address) and we need to confirm an appointment within the next 24 hrs. Otherwise, the job will be reassigned to another provider without notice. Please confirm via our online portal or call us back at (please refer to [Informational: Basic Service Ops Guidelines and Rules](/latchel-admin/Service-Operations/Production-Documentation/Informational-Basic-Service-Ops-Guidelines-and-Rules) for the appropriate phone numbers) at your earliest convenience. Thanks!_
   2. **LCN/LVN:**   _Hello! This is **(insert Associate Name)**, I'm a maintenance coordinator calling on behalf of **(insert PM Company Name)**. We have a job assigned to you at (insert Property address) and we need to confirm an appointment within the next 24 hrs. Otherwise, the job will be reassigned to another provider without notice. Please confirm via our online portal or call us back at (please refer to [Informational: Basic Service Ops Guidelines and Rules](/latchel-admin/Service-Operations/Production-Documentation/Informational-Basic-Service-Ops-Guidelines-and-Rules) for the appropriate phone numbers) at your earliest convenience. Thanks!_
2. Send an SMS or email to the service provider using the following template:

<Tip>
  **Service Provider Scheduling Reminder SMS Template**

  This is a reminder from Latchel to schedule the job at (insert Property\* Address\*) within the next 24 hours. This can be done via our online portal or by calling (_please refer to [Informational: Latchel Communication (Phone Numbers)](/latchel-admin/Service-Operations/Production-Documentation/Informational-Latchel-Communication-Phone-Numbers) for the appropriate phone number_). Otherwise, the job will be reassigned without notice. Thank you!
</Tip>

3. Then, contact the Resident via Webchat/SMS using the following template:
   1. **Say something like**: _Hello! This is **(insert Associate Name)** **from the dedicated maintenance line** on behalf of the **(insert PM Company name)**. We are contacting you to see if you have been contacted by the **(insert Service Provider Name)**. We are attempting to confirm that an appointment has been scheduled._
   2. If the resident confirms that an appointment has been set, update the appointment time in the Latchel console.
   3. If the resident does not confirm an appointment, proceed to the deferral steps below:
      1. Locate the task on the Work Order
         1. Defer the task for the next business day at 9:00 AM local time for the contact. Business day is defined as weekdays and does not include holidays. For example, if it's Friday, please defer the task for Monday.
            1. **_Why?_** We are waiting for the Service Provider to confirm an appointment time via SMS or phone call. When this process happens, this will cancel out the deferred task and the task will not return to the queue.
         2. Proceed to Step 4: Steps For If The Service Provider Has Been Contacted 2x Already.

#### **OUTCOME 5**: If the Service Provider says the job has already been completed, then:

1. Educate the Service Provider about their personalized dashboard.
   1. If the Service Provider has critical feedback, please escalate to the Service Provider Manager.
   2. [How to: Navigate Service Provider Profiles](/latchel-admin/Service-Operations/Production-Documentation/How-to-Navigate-Service-Provider-Profiles)
2. Make a note in the work order and say the following to the Service Provider:

<Tip>
  **Service Provider Job Completion Confirmation**

  Thank you for informing me! I will update the work order accordingly.
</Tip>

3. Select "Mark this Job as Complete" under the "Action" button.
4. Select "Request Invoice from Vendor"
5. Locate the task on the Work Order and close the task
6. Proceed to writing an Effective Note in [Step 5.](#)

#### **<u>OUTCOME 6</u>: If the Service Provider answers but can't confirm an appointment after a second attempt, then:**

1. **Locked-in Service Provider or SP has already visited the property** → Do not reassign. Inform the SP that we'll communicate the status to the Property Manager. Proceed to Step 4, section 2.a.
2. **SP is not locked in and has NOT visited the property** → Inform the SP that we'll reassign the WO. Proceed to Step 4, section 2.b.

### **Step 4: Steps For If The Service Provider Has Been Contacted 2x Already**

1. Review Work Order notes for other Service Providers who have already been contacted.
   1. Note: This step is required to prevent Ops Associates from calling the same Service Providers again, especially if a Service Provider has already denied the job.
      1. Take the time to review the history of Notes from both Ops Associates and the System. Remember that Service Providers have the option to communicate with Latchel through their own Service Provider Interface.
      2. [How to: Navigate the Service Provider Interface](/latchel-admin/Service-Operations/Production-Documentation/How-to-Navigate-the-Service-Provider-Interface)
2. Identify the type of Service Provider currently assigned to the Work Order:
   1. **Locked-In Service Provider OR Service Provider Has Already Visited the Property:**
      1. **Locked-In Service Provider:** A Locked-In Preferred Service Provider is one that the Property Manager has deemed as mandatory for the Work Order.
      2. **Service Provider Has Already Visited the Property:** The Service Provider has already been to the property and there is proof the visit was completed (e.g., visit notes, photos, resident confirmation). This SP is not necessarily locked in or mandatory — however, because work has already begun, they should not be reassigned.
      3. **In either case**, do not remove the SP from the job. Create a task to assign the Work Order to the Property Manager for next steps.
         1. First, the Ops Associate should make sure to close the existing task that was initially assigned to him/her (Ops Associate).
         2. Then, click on the "New Task" tab in the Work Order (see red arrow and box in the screenshot directly below).
         3. Fill out the Create task form with the following [Informational: Basic Service Ops Guidelines and Rules](/latchel-admin/Service-Operations/Production-Documentation/Informational-Basic-Service-Ops-Guidelines-and-Rules) information:
            1. **Subject: Action Required: PM Instructions or Information Needed**
            2. **Who is this task about?:** Select the Service Provider
            3. **Select Date and Time:** Leave this blank. The reason for this is to send the task to the PM right away rather than for a set time.
            4. **Assign to User Group:** PM
            5. **Assign to a User:** Leave this blank. The reason for this is because leaving it blank will send the task to all PMs that are listed within the user group chosen.
            6. **Task Priority Level:** Choose priority based on the WO severity. Follow the current guidelines (see below):
               1. Emergency Severity = Highest Priority
               2. Urgent Severity = High Priority
               3. Normal Severity = Medium Priority
            7. **Cancel Action:** Should always be "Cancel only on Completed or Canceled States".
            8. **Task Description:** Copy/Paste the following template and only edit or verify the 4 fields in pink.
               <Tip>
                 **Latchel Blurb**
                 Hello (insert _PM Name_),
                 We have created this task for you following two unsuccessful attempts to contact (insert _Service Provider Name_) to schedule (_or whatever **specific** piece of information we need from the Service Provider_). We called, left a voicemail and sent an SMS (_or swap for email if the Service Provider's phone number is not textable_) for each attempt, but unfortunately they are still unresponsive or have been unable to confirm an appointment and are preventing the Work Order from moving forward. Could you kindly let us know how you want to proceed? Thank you!
               </Tip>
      4. Then press "Save Task".
         1. **‼️IMPORTANT:** Please note that creating this task **DOES NOT** change the status of the Work Order.
   2. **All Other Service Provider Types (SP is NOT locked in AND has NOT visited the property):<u>:</u>** If you are dealing with a preferred vendor that is **NOT** locked-in or any other type of vendor, please follow the steps below:
      1. If there are ✅ more Preferred Service Providers on the list, remove the current service provider through the "Action" button:
         1. If the vendor automation hasn't exhausted the preferred vendors list yet, our system will continue to offer the job to the remaining vendors on the list. You can tell that the vendor automation hasn't been exhausted if you see the note saying that the vendor contact queue is active

            </Frame>

            </Frame>
         2. If the list has been exhausted by vendor automation, the Ops Associate should then call each preferred vendor that hasn't been called yet or hasn't rejected the job to offer the job and get it scheduled. **<u>Please make sure to log all call attempts in the Work Order notes.</u>** <br /><br />You can tell if the list has been exhausted by auto-assign if you see the note saying that the vendor contact queue has been exhausted You can also tell if the list has been exhausted by vendor automation if you see a task created with the description: "all preferred vendors have been contacted, but none of them have accepted the job".       2. If there are ❌ no more new Preferred Service Providers to contact, review the summary icons in the Property Manager section of the existing Work Order interface and check to see if the PM is "opted-in" or "opted-out" of the Latchel Contractors Network (LCN).
         1. If the Property Manager is **"Opted-In"** to LCN:
            1. Start contacting LCN Service Providers.
            2. If ALL LCN Service Providers have been exhausted, please create a new task for "Source a Vendor" and assign it to the "Source Service Provider" user group.
         2. If the Property Manager is **"Opted-Out"** of LCN:
            1. Create a task to ask for instructions from the Property Manager and assign it to the PM user group.
            2. If the PM responds requesting to enable LCN/LVN, proceed with guidelines outlined in [Product Support Team vs Ops Agents](/latchel-admin/Service-Operations/Production-Documentation/Product-Support-Team-vs-Ops-Agents).

### **Step 5: Write Effective Notes**

1. Write a Note in the existing Work Order, including the Assembly Ticket # (if available).
   1. The note should include the following information:
      1. Summarize the conversation.
      2. Where you left the message (i.e. voicemail, SMS, email, webchat).
      3. Any actions you took to change and assign a new Preferred Service Provider.
      4. If you have escalated, transferred, or deferred the task, summarize what led you to execute one of these actions.

### Handling a multi-day work order

1. If a job is expected to take multiple days and the service provider has confirmed the start and completion date, create a single appointment window that covers the entire duration, up to a maximum of 7 days.
   1. 📝 NOTE: If the service provider is unable to provide an exact time, negotiate an estimated duration and set a placeholder appointment accordingly.
      <Frame>
        ![image-20250409-231204.png](/images/SVC-500.png)
      </Frame>
2. Let the Service Provider know they are expected to coordinate with the resident on a daily basis.
   1. **Say something like**: _“Hey \[SP Name\], we've set a multi-day appointment window to give you flexibility. Please reach out to the resident directly each day to confirm your arrival time. Let us know if anything changes so we can keep the job notes up to date!"_
3. Add a special note to the work order to indicate it’s a multi-day job, so any follow-up agents are aware. If the SP shares an update (delay, schedule change, etc.), log it in the notes so future agents are in the loop.

## 🧠 What This Process Is Trying to Solve

<Info>
  This process ensures resident comments on completed work orders are not missed or delayed. Ops reviews each task promptly, coordinates follow-ups with the resident, SPs, PMs as needed, and resolves issues without waiting for a new ticket or recall.

  It standardizes how Service Operations handles system-created tasks titled: **Task Created: Resident left comments on job: "WO Title"** — emphasizing quick assessment, only necessary actions, accurate documentation, and maintaining WO momentum and customer satisfaction.
</Info>

## 🕒 When to Extract/Review These Tasks

<Info>
  - **Cadence:** Check the Tasks queue for resident survey/comment tasks periodically throughout your shift ("every now and then"). These can arrive at any time of day.
  - **Typical volume:** 1–3 tasks per week.
  - **Priority:** Treat as a priority queue item. Review and take action promptly when found; do not wait for a scheduled sweep.
</Info>

## 📋 Step-by-Step Process

<Info>
  **How these tasks are generated**

  After a work order is completed, residents may be invited via SMS to leave a review. If they submit a rating (1–5 stars) and/or comments, the system creates a task titled "Task Created: Resident left comments on job: 'WO Title'". These tasks will be initially assigned to the Shift Support group for daily monitoring and review by Ops Support. After Ops Support reviews and takes any needed action, they will change the Assigned Group to PSS Investigations to complete their remaining work on the task.
</Info>

### Step 1 — Assign the Task to Yourself

Assign the task to yourself.

- Refer to [this guide](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Work-the-Tasks-Queue#how-to-work-the-tasks-queue).

### Step 2 — Review the Task and Comment Context

<Warning>
  Do not act solely on the task title. Always read the full resident message and WO history to avoid duplicate or wrong actions.
</Warning>

- Open the task: confirm title matches pattern **Task Created: Resident left comments on job: "WO Title"**. Read the resident's comment in full context:

### Step 3 — Determine Severity and Action Need

<Note>
  Ask yourself: Is further effort needed? Does it require Ops action?

  - **Informational** = _update/acknowledgment with no change to plan (e.g., "Thanks," "Issue is resolved")._
  - **Action-needed** = (maintenance issues only) anything that implies a problem, request, commitment, or decision is required (e.g., new issue, unresolved/recall, ETA/scheduling, escalation).
    - **NOTE:** If the resident's comment is vague or you cannot confirm the issue is resolved: Mark it as "Action-needed" and follow up to clarify (e.g., request current status, outstanding issues, or needed appointment details).
</Note>

- If no action is needed: Go to Step 7.
- If action is required or you believe a check-in with the Resident/SP/PM is needed, proceed with the Step 4.

### Step 4 — Identify the Root Cause of the Feedback

Investigate and review the work order to understand what happened and identify the root cause of the pending issue.

Refer to the [Sample Scenarios](#sample-scenarios) below.

### Step 5 — Identify Owner of Next Step (Ops vs PM)

- If managed by PM and process indicates PM ownership → escalate to PM via call (PD/EH) or task (non-PD/EH or non-emergencies)
  - Refer to [this SOP](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/Service-Ops-Guidelines-in-Determining-Active-PM-Management-on-a-Work-Order#service-ops-guidelines-in-determining-active-pm-management-on-a-work-order) to determine whether the issue is actively managed by the PM.
- If not managed by the PM, proceed as usual on how Ops takes action on resident reported issues.

### Step 6 — Take the Correct Action

- If contact is required, Ops Support does not need to make the contact directly. They can take the needed action and create a task for an associate (TS for emergencies/PD/EH and Ops Associate for non-emergencies) to complete it.

<Note>
  These requests are urgent and must be monitored and actioned as soon as they are received.
</Note>

- In the task description, specify what is needed (e.g., contact the resident/SP/PM for clarifying details). Follow the corresponding SOPs when handling the issues.
- If capacity permits, Ops Support may take action on simple tasks (e.g., creating task to PM (no other action required, WO submission (non-complex), etc.)

### Step 7 — Document and Reassign to PSS Investigations

1. Document the following on your notes:

- Resident comment summary
- Decision (info only vs action-needed; emergency vs non-emergency)
- Actions taken and next owner (Ops/PM/SP) with timelines
  - If action was taken, link or reference any follow-up task(s).
  - If info only, state "No action required—informational."

2. Remove yourself from the assignee.
3. Assign the task group to **PSS Investigations**.

<Check>
  **Best Practice:** If you create additional tasks (e.g., SP follow-up), include the resident comment context so future agents have full visibility without hunting through threads.
</Check>

## 🧪 Sample Scenarios

<Expandable title="Example A — Informational Only">
  - Resident: “Issue is resolved after the visit. Just FYI.”
  - Resident: “No further help needed; everything’s working now.”
  - Resident: “Confirming the appointment for tomorrow 2–4pm.” (no change required)
  - **Action:** Read the resident comment in full context. Quick WO scan only if there are triggers of incomplete actions from Ops (tasks left open, etc.).
    Then: Document only — add a brief WO note (e.g., “Informational update; no action required”). Reassign the task to PSS Investigations.
</Expandable>

<Expandable title="Example B — Recall/Unresolved">
  - Resident: “Sink still leaking after visit.”
  - Action: **Investigate the root cause and review the work order (WO), including:**
    - Resident comment context
    - WO timeline/history
    - Last status/notes and last SP visit outcome
    - Photos/invoices and communications
    - Pending tasks and any PM activity in last 48 hours (if relevant)
    Then: Contact SP for re-visit; confirm earliest slot; update WO and resident; notify PM if policy requires. Reassign the task to PSS Investigations.
</Expandable>

<Expandable title="Example C — Emergency Trigger">
  - Resident: “Smell of gas, headache.”
  - Action: **Investigate the root cause and review the work order (WO), including:**
    - Resident comment context
    - WO timeline/history
    - Last status/notes and last SP visit outcome
    - Photos/invoices and communications
    - Pending tasks and any PM activity in last 48 hours (if relevant)
    Then: Follow emergency SOP immediately (dispatch/escalate per process). Document thoroughly and assign the task to PSS Investigations.
</Expandable>

## 🎯 When to Break This SOP

Do not break or deviate from this SOP on your own authority. Always escalate to an Ops Support specialist or follow explicit instructions if you believe an exception is necessary.

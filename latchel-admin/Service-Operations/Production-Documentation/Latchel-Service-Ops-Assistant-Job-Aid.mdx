## What Is It?

The Latchel Service Ops Assistant is a Chrome extension that sits on top of app.latchel.com. It surfaces contextual tips, checklists, and data during work order (WO) tasks so associates make fewer mistakes and move faster — especially during troubleshooting and emergency workflows.

<Note>
As of August 6, 2026: use the plugin's **Next Task** feature to manage your work instead of the task filters previously used. Next Task automatically applies the correct priority order within your queues, and also decides which queues you even see based on your live status in Latchel — so you no longer need to switch between separate task filters to decide what to work on next. See "Task Prioritization" and "How Next Task Picks Your Queues" below for details.
</Note>

## Installing & Logging In

<Accordion title="Steps to Install and Login">
- **Step 1 —** Install from the [Chrome Web Store](https://chromewebstore.google.com/detail/latchel-service-ops-assis/jnpnnoibhffecliboocloalbfmofgfge?authuser=0&hl=en).
- **Step 2 —** Log in with your @latchel.com Google account on any [app.latchel.com](http://app.latchel.com) page. Only http://latchel.com  team members can use it.
- **Step 3 —** If you don't see expected features, restart Chrome and log back in — this resolves most sync/update issues.
- **Checking version —** Check your installed version any time via the gear (Settings) icon after logging in. This job aid reflects plugin version **0.5.3** (current as of 8/12/26).
</Accordion>

## Keeping It Updated

The plugin updates frequently. When Ops leadership posts an "IMPORTANT UPDATE" like the 0.5.0 release, force-update by restarting Chrome and/or revisiting the plugin's Chrome Web Store page. Routine minor updates apply automatically on browser restart and don't require action.

## Task Prioritization

<Warning>
**Important:** The plugin's views can show a task in one queue even when a more time-sensitive task is sitting in another queue. Screen position or a queue's age bar is not the priority signal, and a task's queue/type name (e.g. "Service Provider Followup" vs. "Resident Followup") has **no effect** on which task comes first.
</Warning>

When two tasks are compared, Next Task checks the following in order — it only moves to the next check if everything above it is tied:

1. **Is it a Troubleshooter-queue task?** A task in the Troubleshooter queue always comes first, regardless of how urgent or severe the other task is.
2. **Is it on an emergency work order?** Emergency beats non-emergency.
3. **Is it flagged Urgent?** This is separate from Emergency — a task can be Urgent without being an Emergency. If one task is flagged Urgent and the other isn't, the Urgent one wins here, before due time is ever considered.
4. **What's its Priority level (Highest/High/Medium)?** This comes from the task template and is set automatically:
For example, "Resident reports issue not resolved" is auto-set to High, while "Emergency Not Confirmed Complete" is auto-set to Medium — that's intentional. Responding to a resident who says something still isn't fixed should beat confirming completion with a service provider, even if the service-provider task is older.
  - Emergency-type tasks → **Highest**
  - Urgent-type tasks → **High**
  - Normal-type tasks → **Medium**
5. **Which one is older (due time)?** Only used as the tiebreaker if everything above is identical — the task that's been waiting longer goes first.

Because Priority (step 4) is checked before age (step 5), an older task can still be outranked by a newer one if the newer one has a higher Priority, Urgent flag, or Emergency status. If a task's spot in the queue looks off, check Urgent/Emergency flags and Priority before assuming it's a bug.

When in doubt, use **Next Task** — it applies this order for you automatically.

## How Next Task Picks Your Queues (Status-Based)

Next Task doesn't just sort tasks — it also decides **which queues you see at all**, based on your current status in Latchel and your team/user-group memberships.

### View modes (set in Settings)

- **Status-based (default)** — the queues shown depend on your current status. This is the default for everyone going forward.
- **Team membership** — queues are based on which teams/user-groups you belong to, regardless of status.
- **All queues** — shows everything.
- **Custom** — a saved, named list of queues you choose yourself. You can save, name, and switch between multiple custom lists from Settings or the queue view (renaming only happens in Settings). Old saved defaults automatically migrated into a custom list.

### Core rule: user group membership decides what you can see

<Note>
A queue is only ever surfaced to you if you're a member of that queue's **user group in the Latchel admin console** (Settings → User Groups), not an informal "team" name used in Slack. If you believe you should see a queue (e.g. SMS/Webchat) but don't, confirm your console user-group membership with a lead before assuming it's a bug — informal Slack team names don't always match the console groups that actually drive this.
</Note>

### What each status shows

| Your status | What Next Task shows you |
| --- | --- |
| Training | Queues you're a member of by default, plus your Training status with a quick way to change it. |
| On Break | Your on-break status with an inline status-change option. Does **not** suggest a next task. |
| In a Meeting | Queues you're a member of, plus a quick inline status change. |
| Unavailable | Your unavailable status with an inline status-change option. |
| Available | Queues you're a member of by default. **Ops Support and Leadership see ALL queues** when Available. |
| Inbound Calls | Assembly Operations Email Team queue. If you're also in the SMS Webchat group, you'll also see unclaimed/available conversations, then Operations Associate tasks that do **not** say "Phone Call Required." |
| Emergency Tasks | Troubleshooter queue and the Assembly Emergency Admin queue. |
| Administrative Emergencies | Troubleshooter queue and the Assembly Emergency Admin queue. |
| SMS Webchat | Troubleshooter, Scheduling, Assign Service Provider, Service Provider Follow-up, Resident Follow-up, and Operations Associate queues. |
| Non-Emergency Emails | Assembly Operations Email Team queue — reserved for temporary relief when Support assigns someone to a spike in emails. |
| Non-Emergency Tasks | Scheduling, Assign Service Provider, Service Provider Follow-up, Resident Follow-up, and Operations Associate queues. |

### If your queues run empty

If your standard status-based queues are completely exhausted, the plugin shows a banner ("standard work queues are empty! pulling from your available skills") and falls back to prioritizing by team membership instead. At that point, exclusion rules like the "no Phone Call Required" filter on Inbound Calls no longer apply.

### If you're not on any team

If you're not a member of any team/user-group, you'll see **all queues** by default, with a flag noting this in Settings.

## Idle Status

- The plugin shows you as **"idle"** after **10 minutes** of no interaction with the plugin window. Any interaction resumes active status immediately.
- This is **local to the plugin only** — it does **not** change your actual status in Latchel. (It's designed this way so the plugin isn't checking in with the database every minute while you're away.)
- It's a useful signal — for you or a lead — that someone may be away from their desk without setting "On Break," or that their computer/network may have frozen. It is not itself a status change, so remember to set your real status if you're stepping away.

## Amazon Connect Capacity Alert

<Note>
This alert only shows for members of the **Ops Support** or **Leadership** user groups.
</Note>

As of 0.5.3, the plugin actively warns Ops Support/Leadership when the Amazon Connect call queue is understaffed and at high risk of call rollover, instead of relying on someone noticing it on the Amazon Connect dashboard.

- **No one logged in** — most severe. Tells you whether anyone is even assigned to the phone queue in Latchel but not logged into Amazon Connect, or whether no one is assigned at all.
- **No one available** — people are logged in, but everyone is either on a call or away/offline, so there's no buffer for the next call.
- **Resolved** — once someone becomes available, the alert auto-dismisses on its own with a countdown, so you don't have to manually clear it.

The alert includes an audio signal by default (can be overridden with your own sound).

<Note>
**Idle status exception:** Ops Support/Leadership users normally go idle after 10 minutes like everyone else, but while the Support Dashboard is open, this specific alert check keeps running for up to **2 hours** of inactivity (as long as the tab stays open — it won't refresh if the tab isn't visible). This is so the alert can still catch you even if you've stepped away from your keyboard but left the dashboard open.
</Note>

## Quick Troubleshooting

| Symptom | What to do |
| --- | --- |
| Not seeing a feature everyone's talking about | Confirm your version in Settings, then restart Chrome and log back in. |
| Getting logged out frequently | Update to the latest version — this was a known issue fixed in 0.4.2. Still happening after updating? Report it. |
| Latchel feels slow | Force-update to 0.5.0+; a database-load issue causing slowness was fixed in that release. |
| Unsure which task to work next | Use Next Task — it's the primary way to pick up work and always applies the priority order automatically. |
| A queue you expect (e.g. SMS Webchat) isn't showing up | Check your **console user-group membership** in Latchel (Settings → User Groups) — Next Task follows the console groups, not informal Slack team names. Ask a lead to confirm/update your group if needed. |
| Still looking for the old in-app Tasks page | It was replaced in 0.5.2 by the plugin's own task list, which reflects the official prioritization logic — use Next Task or All Queues in the plugin instead. |

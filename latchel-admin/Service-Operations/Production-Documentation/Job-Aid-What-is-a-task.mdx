## 🧠 What This Process Is Trying to Solve

<Note>
  _We want to prevent duplicated efforts, missed follow-ups, and customer complaints when manual intervention is needed on a work order. The goal is to ensure every task is clearly tracked, assigned, and completed so that work orders return to the automated process as quickly as possible—saving time, reducing errors, and ensuring a smooth experience for customers and property managers_
</Note>

Latchel is a cloud-based software that automatizes maintenance requests from residents and connects them to Service Providers that can take care of them. In the process, Latchel gathers all the necessary information to make appointments possible. While Latchel carries out most of the process automatically, some situations require someone to take action. When these situations emerge, Latchel will create a task.

<Note>
  Any specific SOP for certain situations should take precedence over this job aid.
</Note>

<Note>
  **Note:** Any follow-up that requires a call should be handled by associates outside the Call Center. Call Center associates cannot log out to make outbound calls, so they should create a task for another Ops associate to take action (Operations Associate Group).
</Note>

<Note>
  \*\*Attention: \*\*For agents handling tasks for both emergencies and non-emergencies.

  Before you begin working on any task, \*\*ensure you view all open tasks for the customer you are following up on \*\*(resident, service provider, owner). This step is crucial to avoid duplicating efforts and customers complaints, and to ensure we always get it right the first time.

  **⚠️ Before taking action on any task, confirm that the task is associated with the correct Work Order.** Cross-reference the task details with the WO to ensure you are not acting on a task that was mistakenly assigned to the wrong Work Order.

  For detailed instructions on how to handle the tasks queue and view all open tasks, please refer to the following link: [How to: Work the Tasks Queue | Handling the Task](https://help.latchel.com/how-to-work-the-tasks-queue)

  For information on the frequency and number of times you should contact customers, please refer to[Informational: Basic Service Ops Guidelines and Rules](https://help.latchel.com/informational-basic-service-ops-guidelines-and-rules)
</Note>

## 📋What is a task?

A task is a piece of work to do or undertake to put the work order back in its automatic process. The Latchel system will create a task automatically when it requires further information or for a specific action that it cannot take on its own. Property Managers and the Latchel internal team can create tasks manually.

## 🛠️How to create a task?

<Note>
  ### ✅ Required Rule: Do not leave a Work Order without a task

  Associates must ensure there is always an **active task** on the Work Order that matches the **current status** and the **next required action**.

  **You may only leave a Work Order with no open tasks if the Work Order is in a final state:**

  - **Completed**, or
  - **Cancelled**

  For Autopilot WOs, refer to [How to: Handle Autopilot WOs](https://help.latchel.com/how-to-handle-autopilot-wos).
</Note>

By changing a work order status, a respective task has to be created

1. Work Order Change Status
2. Click “Action” then select the reason. It will bring the work order to the destination status.
3. Continue to fill in the necessary fields then click “Submit”
4. Manual Creation
5. From the “Action” button, click “Create Task”
6. Continue to fill in the necessary fields then click “Create Task”
7. System will then generate the task

Remember: What's needed on the job should reflect the work order status.

## 📝Task Fields

Tasks in the Latchel Dashboard are made up of the following fields:

1. **_A subject_**\*\* \*\*to describe the general situation in one sentence.
2. **_Task Subject_** to select a contact. This is the person that we need to get in touch with to carry out the task.
3. **Due Date** to set the day and time that the task will be due. It is on this date that the system will show the task in the to-do bucket for Operations Associates. Keep in mind this is in property time.
4. If the task has to be assigned to the Troubleshooters user group and the action has to be done in immediately, it is recommended to set the task for the current date and the property's local time. The reason for this is to send the task to the Troubleshooters right away rather than for a set time. Specific SOPs can override this rule if instructed otherwise.
5. If the task has to be assigned to the PM Group, it is recommended to set the task for the current date and the property's local time. The reason for this is to send the task to the PM right away rather than for a set time.
6. **User Group** to send the task to the group of people who will execute it.
7. \*\*The user \*\*has to be left blank. The reason for this is that leaving it blank will send the task to all users that are listed within the user group chosen.
8. **Priority** Choose priority based on the WO severity. Follow the current guidelines (see below):
9. Emergency Severity = Highest Priority
10. Urgent Severity = High Priority
11. Normal Severity = Medium Priority
12. **Completion Action to** indicate if the task should stay open until it reaches a state
13. Complete task on any job state change - most of the tasks are set as default with this option
14. Never complete on any job state change - The task is assigned to “Troubleshooters” user group; the task is for payment follow-up
15. Complete task only on Completed or Cancelled job states
16. \*\*Task Description \*\*to send a message to the person that needs to perform the task.

<Note>
  **Task Description Requirements**

  - Include a brief summary of what happened.
  - Be specific about the next steps required for the next person.
  - Specify who should be contacted to complete this task successfully.
</Note>

## 👥List of User Groups and when to assign them

The below list of groups is being used by Operations Associates when a manual task is created.

**Latchel User Groups**

- **Operations Associate** - This is selected when both the resident and the service provider have to be contacted about the task.
- **Service Provider Followup** - To be selected when something has to be followed up with the service provider e.g. follow up on the estimate.
- **Resident Followup** - To be selected when something has to be followed up with the resident e.g. follow up on the photos requested by the property manager.
- \*\*Payment Issues and Disputes \*\*- To be used anytime a payment method has already been attempted but did not go through and/or the service provider is reporting a dispute in the payment. The service provider would like to follow up on a payment that was not received.
- \*\*Source Outside Network \*\*- To be used when the Latchel queue has been exhausted and we have manually attempted to assign all LCN and Preferred vendors. A task assigned to this group should only be created if the property manager has opted in to use LCN vendors.
- **Payment Processing** -  All tasks associated with payments that have not had a card issued or another form of payment attempted.
- **Troubleshooter -** Select when the issue is an emergency, worsening, or ambiguous and requires TS review. See [Task Assignment Guidelines](https://help.latchel.com/sop-work-order-follow-ups-and-updates) for details.
- \*\*Resident Responsible: \*\*Any task needed for a Resident Responsible WO should be assigned to this group.

**PM User Groups**

- **Default User Group/ PM Portfolio Name** - If the action is pending from the PM, this group has to be assigned

The following group should not be used by an associate:

The following groups exist and are mostly assigned if a task is system-generated. **_Operation Associates must not use these for manually-created tasks_**.

- Shift Support
- Scheduling
- Assign Service Provider
- Leadership
- Customer Success
- Trainer
- CCS Investigations
- Warranty Claim
- Housecall Pro Pilot

## 🔚Completing or Deferring a Task

<Note>
  **‼️IMPORTANT NOTE:** Tasks deferred to the next day or business day must always be scheduled for **9:00 AM in the property's local time**, unless the customer's critical notes explicitly indicate different working hours.
</Note>

After working on a task, Operations Associates must complete it or defer it.

- A task is completed when the actions taken are successful, allowing it to move forward automatically again. Actions are deemed successful when they eliminate the need for further follow-ups, such as moving the work order from one status to another. However, it is important to note that a successful contact does not guarantee the success of the actions taken.
  - **Non-emergency work orders**
    - A task can be deferred to the next business day after we’ve taken action to contact a customer but the customer was unresponsive.
    - \*\*‼️IMPORTANT: \*\*A task should not be deferred if no action is taken at all, this includes when it’s after-hours and you wouldn’t be allowed to contact a customer for that specific task. It’s important to not defer a task when no action was taken so that we can work on it first thing next business day.
  - **Emergencies**
    - A task can be deferred to the next day (for non-property damaging or non-extreme habitability situations) after we’ve taken action to contact a customer but the customer was unresponsive.
    - For more information on our general follow up guidelines, Refer to [https://latchel.atlassian.net/wiki/spaces/OPS/pages/edit-v2/776701198#Follow-Up-Procedures](https://latchel.atlassian.net/wiki/spaces/OPS/pages/edit-v2/776701198#Follow-Up-Procedures)
- A task must be updated with any new information or instructions if a customer (Resident, Property Manager, Property Owner, or Service Provider) replies after the task has been deferred. Reset the task status to the current property time so the TS associate can take immediate action. If the task moves to “Invalid Time,” a new task must be created to ensure the request is handled properly.
  - Refer to FAQ 1 [SOP: Work Order Follow-ups and Updates](https://help.latchel.com/sop-work-order-follow-ups-and-updates)

### 🗃️⏳Bulk Deferral

The bulk deferral feature allows Latchel Agents to choose multiple tasks on a single user’s task page and defer them within the same action. Please note the following important notes and limitations about the bulk deferral functionality:

- The bulk deferral functionality defers the task due date to the **next business day** from the current due date.
  - As a result, if you choose 2 tasks to bulk defer where one is currently due for Monday 11/22 and the other is due for Tuesday 11/30, then they will be deferred for Tuesday 11/23 and Wednesday 12/1, respectively.
  - Any tasks that are overdue will be deferred to the next business day from the current day. So if it’s Thursday 12/23 and you have an overdue task that was due Monday 12/20, then that overdue task will be bulk deferred for the next day (Friday 12/24).
- Tasks are also deferred for the next business day at 8:00 AM local time of the property in the WO.
  - **⚠️<u>WARNING:</u>** If the user’s time zone and the property’s time zone are different, then there may be some churn. However, these should be edge cases since the PMs or service providers servicing certain properties are likely to be in the same time zone.
- Next business day is defined as the next day that’s not a weekend or a US holiday. For example:
  - All tasks with a due date on Friday will be bulk deferred for the following Monday.
  - If a task has a due date of 12/24 (Christmas Eve) and you choose to bulk defer it, it’ll skip the holiday (12/25) and defer to the next business day after (12/26).

<Note>
  **‼️IMPORTANT<u>:</u>** If you’d like to defer for a timeframe outside of the next business day at 8:00 AM local time of the property, you will have to do so manually within the WO.
</Note>

## 🎯 When to Break This SOP

- **Immediate Risk or Emergency**: If following the SOP would delay response to an emergency, create a safety risk, or cause harm (e.g., life-threatening situations, major property damage), you must escalate immediately and follow emergency protocols instead of the standard process.
- **Scenario Not Covered by SOP**: If you encounter a situation not addressed by the SOP, or you are unsure how to proceed, pause and escalate to the Operations Support Specialist for guidance. Do not break the SOP on your own.

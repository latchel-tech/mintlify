## 🧠 What This Process Is Trying to Solve

<Note>
**We want to empower Service Operations to deliver faster, more accurate, and more personalized service by leveraging Harmonia’s AI-powered Intake Settings.**
The goal of this change is to replace the old, complex Severity/Responsibility settings with a flexible, rule-based system that allows Property Managers to define what counts as an emergency, non-emergency, or requires approval—at the company, portfolio, or property level. This reduces confusion, speeds up triage, and ensures residents and PMs get the right response every time.
</Note>

int

<Note>
⚠️ **Important Warning**
Harmonia and Harmonia X **do not override existing processes**.

- Harmonia and Harmonia X **only replace Severity/Responsibility and Emergency Temp for PMs.**
- **All other processes remain unchanged** and must continue to follow established procedures.

TS members no longer need to update the ***problem***** and *****location*** fields on work orders if they are missing or incorrect. These fields are not required for automations, and while updating them doesn’t cause issues, it is unnecessary and saves time to skip.
</Note>

# Harmonia Overview

<Note>
#### 🔍**What pain point or risk is this solving?**

- Eliminates the need for 140+ manual severity settings and separate emergency temperature configs.
- Reduces misclassification and delays by using plain-language rules and real-time data.
- Prevents inconsistent service and escalations due to unclear or outdated settings.
- Ensures Service Ops always references the most current, PM-specific rules for severity.
</Note>

<Note>
#### 🔄What’s Changing

- **Old Process:**
Service Ops referenced Severity/Responsibility settings and Emergency Temperature Settings, which were configured separately and often confusing for both Ops and PMs.
- **New Process with Harmonia:**
  - PMs write custom rules in plain language to define severity and approval requirements.
  - Rules are applied at the company, portfolio, or property level.
  - The system uses the work order summary and resident responses to determine severity.
  - All rules and outcomes are logged in the work order’s Intake Processing Details for transparency
</Note>

<Note>
#### ⚙️When and Where to Apply Harmonia Intake Settings

- **Who is impacted:**
All work orders for PMs across all queues — TS, CC, and SMS/Webchat. Harmonia is enabled across all PM accounts.**📌 Queue-specific expectations:** CC and SMS/Webchat associates are expected to act when they spot a severity misclassification in the course of what they are already doing — not to proactively audit intake settings on every interaction. When a mismatch is apparent:
  - If it is clear from intake settings → correct the severity directly.
  - If live troubleshooting or further assessment is needed → create a TS task. Do not troubleshoot the situation yourself or route to Support as the default.
- **When to use:**
Whenever you are triaging or troubleshooting a work order always reference the Intake Settings (not Severity/Responsibility).
</Note>

## 📋 Step-by-Step Process

<Note>
**Before proceeding with the steps below and contacting the resident, please ensure that you have checked whether any other work orders were generated via intake that also need review. **For guidance, refer to: [Handling Multiple Work Orders Generated by Harmonia Intake](https://help.latchel.com/latchel-admin/Service-Operations/Service-Ops-Handling-Multiple-Work-Orders-Generated-by-Harmonia-Intake)

### Step 1 - Determining the Work Order Severity

Step 1 is to correctly determine the **work order severity**. Before taking any action, confirm whether the issue is **emergency, urgent, normal, needs approval, or resident responsible** based on the Property Manager’s Intake Settings. This ensures the work order follows the right path and aligns with the PM’s expectations and subscription type.

**💡Tip:** If the **Intake Settings** list is long, you can use the **Test Issue** feature. This will determine the severity settings automatically based on the PM’s listed rules.

**📝 Temperature-Based Rules — Key Guidance:**

- **Outside temperature rules:** Harmonia uses a **3-day weather forecast** by default. If the PM's rule specifies a different timeframe (e.g., "in the next 24 hours"), that Intake Setting overrides the 3-day default.
- **Inside temperature rules:** Some PMs set rules based on **indoor** temperature (e.g., "if inside temp is below 60°F"). Harmonia **cannot** determine inside temperature from weather data. If Harmonia did not confirm indoor temperature during intake, the troubleshooter must ask the resident and apply the PM's rule accordingly.
- **Always check:** Whether the PM's rule says "outside" or "inside" temperature before applying the default weather forecast.

<Note>
### Empty Rule Set Guidance

If the Property's Intake Settings display an **Empty Rule Set** (0 rules), do not navigate to the Property Management Company's Intake Settings to determine the work order outcome.

An Empty Rule Set means the property has no configured intake rules and only the property's fallback outcome should be used.

In these situations:

- Review the fallback outcome displayed on the Property's Intake Settings page.
- Apply the property's configured fallback outcome.
- Do not use rules from the Property Management Company's Intake Settings unless specifically instructed by Product or Leadership.

The Property-level Intake Settings always take precedence when evaluating a work order.
</Note>

**💡 Tip:** To quickly find rules for a specific severity, click the severity level tabs at the top of the **Intake Settings** (e.g., **Emergency**, **Needs Approval**, **Normal**, **On-Call**, **Resident Responsible**). This filters the list to show only the rules under that severity, making it easier to locate relevant rules when the list is long.

Sections in Intake Settings:

Each section displays the number of rules configured by the PM, the custom rule descriptions, and the action Latchel will take:

1. **Emergency** – Rules that match emergency situations. *Latchel will begin second level troubleshooting by a live agent.* During intake, these work orders are immediately flagged for emergency handling.
2. **Needs Approval** – Rules where the work order requires Property Manager approval before dispatch. *Latchel will notify the property manager for approval before dispatching a vendor.* If the intake setting indicates "Needs Approval" but you have already received confirmation or instructions from the Property Manager to proceed, you may update the severity to **Normal**—unless the Property Manager specifically instructs you to keep it at a different severity level.
3. **Normal** – Rules for non-emergency issues. *Latchel will start dispatching a vendor.* The system will automatically move the work order to the *Finding Service Provider* state.
4. **On-Call** – Rules where the PM uses an on-call rotation for that setting. *Latchel will begin contacting the selected on-call rotation.* The work order will move automatically to Contacting On-Call.
5. **Resident Responsible** – Rules where the issue is the resident's responsibility. *Latchel will cancel the work order and inform the resident they're responsible for coordination and payment.* Since we no longer handle these, the work order will be cancelled and the resident will be notified.
  - **📝 NOTE**: If you are handling an emergency WO and you have determined it must be Resident Responsible after work order assessment, follow the guidelines outlined in FAQ 3 of [How to Handle Resident Responsible WOs](https://help.latchel.com/latchel-admin/Service-Operations/How-to-Handle-Resident-Responsible-WOs)
6. **If no rules match...** – This is the fallback outcome applied when no rules in the above sections match the work order. It is separated by request type:
  - **Maintenance issues** – Shows the configured fallback state for maintenance-related work orders (e.g., State: Needs Approval). *Latchel will notify the property manager for approval before dispatching a vendor.* Operations must use this setting whenever, after troubleshooting or assessment, they find that no rules apply.
    - **📝 Note:** Always check the **Property Manager's subscription type** (e.g., **24/7 Emergency Only**, **After-Hours Emergency Only**) before finalizing the outcome when no rules match in Intake Settings.
      - If the PM's subscription is **24-hour emergency only** or **after-hours emergency only** and the WO severity is **non-emergency**, the WO should normally be **automatically forwarded to the Property Manager**.
      - If this **does not** happen and the WO is left in **Needs Approval** or non-emergency instead, troubleshooters should **manually forward the WO to the Property Manager** and then **submit a bug report** so the behavior can be corrected.
      - For guidance on subscription types and how work orders should be handled under each, refer to: [Subscription Types](https://help.latchel.com/latchel-admin/Service-Operations/Informational-Latchel-Customers-Customer-Subscriptions)
  - **Other requests** – Applies to requests that are not related to maintenance (i.e., administrative requests). The PM can configure this to send an email notification to a specified address (e.g., Action: Send Email Only to PM default email). *Latchel will send an email notification to the specified address. No work order will be created.*
    - PMs can also create non-maintenance rules at the top of the Intake Settings, similar to how they configure other intake rules.

### The “Test Issue” Feature

<Note>
The “Test Issue” tool is designed to help troubleshooters match complex or lengthy rules in Harmonia Intake Settings to the work order scenario. However, in most cases, troubleshooters should be able to read through the rules and apply the correct severity without relying on the Test Issue. The tool should primarily be used when there are a large number of rules or when the rules are especially complicated and it’s difficult to determine which applies.
</Note>

**Expectations:**

- **Default Approach:**
Troubleshooters should review the Intake Settings and use their judgment to apply the correct severity, as they would for any work order.
- **When to Use Test Issue:**
Only use the Test Issue tool if:
  - The rules are so numerous or complex that it’s not clear which rule applies.
- **Not for Routine Ambiguity:**
Do not default to Test Issue for every ambiguous case. If there is uncertainty, use your troubleshooting skills and the Intake Settings to make a determination.

# Harmonia X Overview

Harmonia X is the next evolution of Latchel’s intake process, leveraging AI to deliver a more intuitive and personalized experience for residents and more accurate work order triage for Service Ops.

### When to Use Harmonia X

- Whenever a work order is submitted by a resident for a property managed by a PM with Harmonia enabled, Harmonia X will guide the intake process.
- Service Ops should monitor for any tasks generated by Harmonia X for manual skill assignment and follow the prompts accordingly.
  - Refer to [Troubleshooters: Handling Skill Assignment Tasks in Work Order Intake (Low Confidence, No Skill Match, and No Skill Assigned)](https://help.latchel.com/latchel-admin/Service-Operations/Troubleshooters-Handling-Skill-Assignment-Tasks-in-Work-Order-Intake-Low-Confidence-No-Skill-Match-and-No-Skill-Assigned).

### What’s Changing with Harmonia X

- **Old Process:** Residents followed a static, point-and-click diagnostic flow, which sometimes failed to capture the true nature of their issue.
- **New Process:** Residents interact with a dynamic, AI-driven flow that adapts to their responses, improving accuracy and resident satisfaction.

### Risks & Mitigations

- If Harmonia X cannot determine the skill, Service Ops must act promptly on the generated task to avoid delays.
- Always review the Intake Settings and Harmonia X outputs before finalizing severity or dispatch actions.

## Escalation Path

**📌 Note on severity misclassifications**

Routing a misclassification to Support is no longer the expected default for any queue. Associates who spot a misclassification should either correct it directly (if clear from intake settings) or create a TS task (if live assessment is needed). Use #ops_assistance_hub only when severity genuinely cannot be determined and neither option applies. If you do escalate, include your reading of the intake settings and your tentative assessment.

- Operations associates/troubleshooters can post their inquiries in the ***#ops_assistance_hub ***channel
- For cases that involve complex scenarios, unusual situations, or edge cases not explicitly addressed in the SOP, Operations Support Specialists can escalate to ***#harmonia-war-room*** channel.
- Any unusual or unexpected behavior from Harmonia and Harmonia X that could negatively affect the customer experience should be documented and reported in **#bug-report**.This includes both:
  - **Feature/flow issues** (e.g., incorrect handling of caller inputs, broken conversation paths, confusing messaging)
  - **System issues** (e.g., downtime, slowness, failures to save or submit work orders, integration errors, data mismatches)

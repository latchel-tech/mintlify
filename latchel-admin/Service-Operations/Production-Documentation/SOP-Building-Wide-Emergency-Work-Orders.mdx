## 🧠 What This Process Is Trying to Solve

<Note>
To reduce vendor confusion, duplicate charges, and unnecessary property-team notifications, Troubleshooters should confirm whether the issue is isolated to **a single unit **or **affects multiple units within the building (e.g., a shared boiler or HVAC system) **before dispatching a technician. The goal is to avoid redundant work orders, save time and costs, and ensure timely, accurate support for both customers and property managers.
</Note>

<Warning>
📌 **When to Use**

This SOP should be applied **only when all of the following conditions are satisfied**:

- Multiple emergency reports or work orders are submitted from **different units within the same building**, occurring within the **same incident window** (i.e., they pertain to the same active issue reported around the same time).
- The issue is likely **building-level** in nature (e.g., a shared boiler or HVAC system serving the entire building).
- The system can be **confirmed as shared** among the affected units.

🚫 **When NOT to Use**

Do **not** consolidate work orders if:

- The issues are **unit-specific** (e.g., a leak in a single unit, a unit-specific heater, or a unit’s electrical panel).
- Confirmation of **shared equipment** cannot be obtained within a reasonable timeframe.

⚠️ **If uncertain:** handle each work order separately and escalate to **Shift Support** for guidance.
</Warning>

## 📘 Definitions

- **Incident:** Multiple reports of the **same issue type**, from the **same building**, within the **same incident window** (e.g., “boiler down” reports occurring close together).
- **Main WO:** The single work order that is **dispatched and tracked** as the source of truth for the incident.
- **Duplicate WO:** Any additional work order from other units for the same building-level incident that should be **canceled**.

## 📌 Verification: Confirm It’s a Shared System

Before consolidating work orders, confirm **at least one** of the following:

1. The Property or Property Manager (PM) has notes or documentation indicating a **shared building system** (e.g., water heater, HVAC system, or building-wide electrical panel).
2. Prior work orders reference a **single equipment tag or location** serving the building.

⚠️ **If neither can be confirmed:** do **not** consolidate the work orders yet. 

## 📋 Step-by-Step Process

<Warning>
When the same issue impacts multiple units within a building, handling separate work orders for each unit can create confusion and may result in duplicate dispatches or other errors. To prevent this, it is essential to **review and identify any existing work orders** related to the same concern within the same building, following the process outlined below.

**For widespread utility outages:** refer to https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/Emergency-How-to-Handle-a-Utility-Issue 

**For duplicate issues affecting a single unit:** refer to https://latchel.atlassian.net/wiki/spaces/OPS/pages/778174469 
</Warning>

### **Step 1: Confirm Building-Level Incident**

1. Confirm the building address
  1. Verify that all reports originate from the **same street address**, even if unit numbers differ.
2. Confirm the issue category
  1. Ensure that the reported problem falls under the **same type of issue** (e.g., boiler down, no heat) and appears to affect the **entire building** rather than individual units.
3. Verify existing work orders
  1. Copy the building’s street address **without the unit number**.
  2. Access the **Property Manager (PM) profile** and open the **Maintenance** tab.
  3. Paste the address into the search bar to display all work orders for units within that building.
  4. Use this information to determine whether a **Main WO** already exists and avoid creating duplicate work orders.

⚠️ **Note:** This step is critical to prevent confusion, duplicate dispatches, and ensure consistent handling of building-level issues.

### **Step 2: Select the “Main” Work Order**

1. Identify the **Main** work order
  1. If a work order (WO) already exists for the incident, select the **earliest created work order **as the **Main**. 
2. **Main Work Order Title (required)**
  - Format: Main WO - (Issue)
  - Example: Main WO - Boiler Down
3. Main WO Notes (required)
  1. **Issue:** Provide a concise 1-sentence summary of the problem.
  2. **Units Reporting:** Maintain a running list of affected units (e.g., Unit 101, Unit 203, Unit 305…).
  3. **Verification Method Used:** Document the method used to confirm the building-level issue (e.g., property note, PM confirmed, prior WO, vendor note).

### **Step 3: Handle All New Work Orders as Duplicates**

For every **new WO** submitted for the **same incident within the same window**:

1. **Do not dispatch** from the new WO. ❌
2. **Add a note to the new WO** 📝
  - Use the following **suggested template** 
📝 “*This appears to be the same building-level emergency affecting multiple units. This unit report is being tracked under Main WO #. No separate dispatch created.”*
3. **Set expectations with the tenant**
  1. Advise the resident that their report is being tracked under the Main WO and that **no separate dispatch will be made**.
  2. Example message (SMS or call):
    1. 🗨️ **Say something like:** *“Hello [Resident Name], your report has been consolidated as part of a building-wide issue and is being tracked under Main WO #. To ensure a coordinated resolution, no separate dispatch will be made for your unit, and the duplicate request will be canceled. We appreciate your understanding.”*
4. **Cancel the duplicate WO**
  1. **Cancel the duplicate WO as inactive** to prevent accidental dispatches.
  2. Ensure the WO is **linked or referenced** to the Main WO.
5. **Update the Main WO**
  1. Add the new unit to the **“Units Reporting”** list.
  2. Copy the **WO number or link **🔗  of the **Main Work Order** to the duplicate work order you are handling.

### **Step 4: Dispatch Only From the Main Work Order **

1. Dispatch from the Main WO only
  1. All vendor dispatches must be initiated from the **Main Work Order**. Do **not** dispatch from duplicate WOs.
2. Verify the Main WO title
  1. Ensure the title clearly reflects the **building-level impact**, e.g. Main WO - Boiler Down
3. Maintain all updates in the Main WO
  1. Record all **vendor updates, approvals, and status changes** in the Main WO to ensure a single source of truth for the incident.

### **Step 5: Notify the Relevant Channel for Visibility** 📢

1. Post updates in the #ops_info_center channel 
  1. Share information in the #ops_info_center channel once the **Main WO** is established.
  2. Update the channel as needed if there are changes to the incident or reporting units.
2. Use the suggested channel update template
  1. 📝“*Building-level emergency consolidation in progress: [Building Address] – [Issue].*  
*Tracking under Main WO #. Multiple units reporting. Please do not dispatch from additional unit WOs.”*

## [❓](https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/How-to-Handle-Emergency-Work-Orders)Frequently Asked Questions

<Accordion title="Q1: What if there is no report yet for this building-wide issue?">
1. Proceed to **Step 1 of this SOP** to verify whether any existing work orders have been submitted for the same issue.
2. **If no existing work orders are found:**
  - Treat the incoming report as a **normal work order intake**.
  - Follow the **standard troubleshooting steps**.
  - Refer to https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-Troubleshooter-Question-Bankfor guidance. 
3. If this work order is designated as the **Main WO**, post an update in the **#ops_info_center** channel to set expectations regarding a **building-wide maintenance issue** (e.g., HVAC, boiler, or circuit breaker).
</Accordion>

<Accordion title="Q2: What if the situation escalates to a property damaging / extremem habitability category?">
1. If the new report indicates the incident qualifies as **PD/EH**, ensure the **EEC is contacted** if they have not already been notified via the **Main Work Order.**
  1. Manually trigger the "**Who Ya Gonna Call**" tool by clicking the Action Menu and choosing this in the options for the correct contact and call order based on time of day and scenario. Associates should review the AI recommendation first, while also verifying the information against the original escalation instructions displayed below.
  2. Refer to https://help.latchel.com/latchel-admin/Service-Operations/Production-Documentation/Job-Aid-PM-Outbound-Communication-for-Emergency-WOs  
2. **Link the calls** to both the recent report and the **Main Work Order** for proper documentation.
  1. Refer to https://latchel.atlassian.net/wiki/spaces/OPS/pages/2744680449 
</Accordion>

## 🎯 When to Break This SOP

**Do not break or deviate from this SOP on your own authority.** Always escalate to an Ops Support specialist or follow explicit instructions if you believe an exception is necessary.

- Safety risk to a resident 
- High risk of property damage, or the issue is escalating rapidly 
- Unable to confirm a shared system (e.g., building has multiple boilers, HVAC systems, or other infrastructure) 🔧
- Reports appear to be separate incidents, not occurring within the same outage window 
- Details are inconsistent across units, suggesting multiple distinct issues 
- Property team or vendor requests separate WOs.
